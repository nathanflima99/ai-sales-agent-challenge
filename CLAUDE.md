# Claude Code Project Guide

## Mission
Build a small, production-minded AI sales analysis service that answers natural-language questions about `dataset/sales.csv`.

## Core architecture
User -> FastAPI -> LangGraph agent loop (LangChain tools) -> validated read-only SQL
-> DuckDB -> CSV -> grounded answer.

The challenge brief explicitly requires an AI agent library. LangGraph orchestrates the
loop with an explicit `StateGraph`, not the prebuilt `create_react_agent`, so the tool
trace, the turn budget and the tool-error handling stay visible in our own nodes.

## Non-negotiable rules
- Keep the solution easy to explain in an interview.
- Prefer the simplest design that preserves correctness, safety, tests, and observability.
- The LLM interprets intent and explains results; DuckDB performs analytical calculations.
- Never send the full CSV to the LLM.
- Never execute arbitrary Python generated by the model. Do not use `eval()` or `exec()`.
- Never use `create_csv_agent` or `create_pandas_dataframe_agent`. They run LLM-generated
  Python through `PythonAstREPLTool` and require `allow_dangerous_code=True`, which is
  remote code execution by design. Generating validated SQL instead is the point of this
  project.
- Do not add RAG, embeddings, a vector database, multiple-agent runtime, Kubernetes, Redis, Celery, or an external database unless a concrete requirement appears.
- Generated SQL must be read-only and validated before execution.
- Treat ambiguous business questions explicitly instead of silently inventing a definition.
- Do not claim causality from weak observational evidence, especially promotion data.
- Keep secrets out of Git. Never commit `.env` or API keys.

## Development workflow
1. Read `IMPLEMENTATION_PLAN.md` before substantial implementation work.
2. Work one phase at a time.
3. State the smallest coherent change to make.
4. Implement it.
5. Run the relevant tests.
6. Summarize changed files, decisions, tests, and the next step.
7. Do not delete or weaken tests just to make them pass.

## Claude project assets
- `.claude/skills/`: reusable project procedures and technical guidance.
- `.claude/agents/`: specialized subagents for architecture, implementation, testing, review, and security.
- Custom commands are intentionally not the primary pattern because current Claude Code treats Skills as the recommended replacement for project slash commands.

## Definition of done for each phase
A phase is done only when its acceptance criterion passes, relevant tests pass, no secret is exposed, and the implementation remains understandable without unnecessary abstraction.
