# Documentation

Optimize the README for an evaluator with five minutes.

Recommended order:
1. What the project does.
2. Architecture diagram.
3. Quick start locally.
4. Docker build/run.
5. Environment variables.
6. Example questions/responses.
7. How to run tests.
8. Design decisions and trade-offs.
9. Security/reliability boundaries.
10. Dataset caveats and limitations.
11. Reasonable next steps.

Commands must be copy-pasteable and verified. Explain why DuckDB/tool calling are used and why RAG/arbitrary Python are not used. Do not market unfinished functionality as complete.
